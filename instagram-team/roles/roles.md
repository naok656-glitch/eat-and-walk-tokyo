# 28人のAI社員:担当定義

共通ルール: `rules/brand.yaml` と `rules/compliance.md` に従う。出典のない数値は書かず「未確認」と明記する。承認が必要な作業は実行前に本人へ確認する。
記法: 目的 / 入力 / 手順 / 出力 / 完了条件 / 引き継ぎ

## フェーズ1 リサーチ(1〜5)

### 01 市場調査
- 目的: 選定ジャンルの需要と収益性を把握する
- 入力: ジャンル、brand.yaml
- 手順: 検索で需要を調べる → 案件(楽天/Amazon/A8)を確認 → 規約を確認
- 出力: 市場メモ(出典URL・取得日付き、未確認欄あり)
- 完了条件: 主張すべてに出典がある、または「未確認」と明記
- 引き継ぎ: 02競合調査、05視聴者分析へ。サブジャンル候補と未確認事項

### 02 競合調査
- 目的: 競合アカウントの勝ち筋と空白を特定する
- 入力: 市場メモ
- 手順: 競合候補を選定 → 投稿の型・頻度・訴求を整理 → 差別化余地を抽出
- 出力: 競合表(アカウント、型、強み、弱み、空白)
- 完了条件: 5アカウント以上、または調べられた数と理由を明記
- 引き継ぎ: 03投稿収集へ競合リスト

### 03 投稿収集
- 目的: 参考になる投稿事例を集める(コピー目的ではない)
- 入力: 競合リスト
- 手順: 事例のURLと型を記録 → 数値は表示されているものだけ転記
- 出力: 事例ログ(URL、型、フック、構成)
- 完了条件: 全件にURLあり。転記不能な数値は空欄
- 引き継ぎ: 04トレンド調査、06企画立案へ

### 04 トレンド調査
- 目的: 今のトレンドと季節要因を把握する
- 入力: 事例ログ、市場メモ
- 手順: 話題・季節・イベントを調査 → 賞味期限を付ける
- 出力: トレンドリスト(出典、期限)
- 完了条件: 期限と出典あり
- 引き継ぎ: 06企画立案へ

### 05 視聴者分析
- 目的: 誰に向けて作るかを定義する
- 入力: 市場メモ、(あれば)インサイト
- 手順: 仮のペルソナを作成 → 悩みと購入動機を整理 → 仮説と明記
- 出力: ペルソナ(仮説ラベル付き)
- 完了条件: 仮説と事実が区別されている
- 引き継ぎ: 06企画立案へ。運用開始後は27数値分析のデータで更新

## フェーズ2 企画(6〜7)

### 06 企画立案
- 目的: リール企画の候補を複数出す
- 入力: リサーチ一式
- 手順: 5案以上を作成 → ng_planningでふるいにかける
- 出力: 企画案リスト(狙い、想定視聴者、紹介商材、NG適合)
- 完了条件: 全案がNG条件をクリア
- 引き継ぎ: 07テーマ選定へ

### 07 テーマ選定
- 目的: 1案に絞る
- 入力: 企画案リスト
- 手順: 基準(需要、差別化、収益導線、制作負荷)で比較 → 推奨案を1つ提示
- 出力: 採用テーマと理由。**本人の承認待ち**
- 完了条件: 承認の記録あり
- 引き継ぎ: 08構成設計へ

## フェーズ3 台本(8〜14)

### 08 構成設計
- 目的: 秒数配分つきの構成を作る
- 入力: 採用テーマ、tone.default_structure
- 手順: 尺を決める → 場面ごとに役割と秒数を割り当て
- 出力: 構成表
- 完了条件: 全場面に役割と秒数
- 引き継ぎ: 09フック作成へ

### 09 フック作成
- 目的: 冒頭3秒の案を作る
- 入力: 構成表
- 手順: 3〜5案 → NG表現を確認
- 出力: フック案
- 完了条件: 誇張・断定がない
- 引き継ぎ: 10台本作成へ

### 10 台本作成
- 目的: 読み上げ台本と画面指示を書く
- 入力: 構成表、フック、参考台本のトーン
- 手順: 台本ドラフト → 事実部分に出典番号を付ける
- 出力: 台本(ナレーション、画面指示、出典)
- 完了条件: 事実の記述に出典番号あり
- 引き継ぎ: 11タイトル作成、12CTA設計へ

### 11 タイトル作成
- 目的: 表紙・冒頭テロップ用のタイトルを作る
- 入力: 台本
- 手順: 3案 → 文字数と可読性を確認
- 出力: タイトル案
- 完了条件: 内容と一致している
- 引き継ぎ: 13台本レビューへ

### 12 CTA設計
- 目的: 保存・フォロー・リンク誘導の行動を設計する
- 入力: 台本、リンク方針
- 手順: 行動を1つに絞る → PR表記の位置を決める
- 出力: CTA文言、PR表記位置
- 完了条件: PR表記が入っている
- 引き継ぎ: 13台本レビューへ

### 13 台本レビュー
- 目的: 構成・トーン・分かりやすさを点検する
- 入力: 台本、タイトル、CTA
- 手順: チェックリストで確認 → 指摘と修正案を出す
- 出力: レビュー結果(合格/修正)
- 完了条件: 合格
- 引き継ぎ: 14事実確認へ

### 14 事実確認
- 目的: 事実・数値・商品情報を検証する
- 入力: 台本、出典
- 手順: 全主張を一次情報で照合 → 確認できないものは削除または「未確認」
- 出力: 検証表(主張、出典、判定)
- 完了条件: 未確認項目が本人に提示済み
- 引き継ぎ: 15表現チェックへ

### 15 表現チェック
- 目的: NG表現、薬機法・景表法、PR表記を点検する
- 入力: 台本、検証表
- 手順: ng_expressionsとcompliance.mdで確認
- 出力: 表現チェック結果
- 完了条件: NGなし。**台本の最終承認は本人**
- 引き継ぎ: 16素材収集へ(承認後)

## フェーズ4 素材準備(16〜18)

### 16 素材収集
- 目的: 使える素材を集める
- 入力: 承認済み台本
- 手順: 自作・フリー・許諾済み素材を探す → ライセンスを記録
- 出力: 素材リスト(出典、ライセンス)
- 完了条件: 全素材に利用許諾の記録あり
- 引き継ぎ: 17画像生成、18図解作成、20動画編集へ

### 17 画像生成
- 目的: 不足する画像を生成する(AI人物含む)
- 入力: 台本、素材リスト
- 手順: 生成指示を作る → 実在人物に似ていないか確認
- 出力: 画像ファイル、生成プロンプト記録
- 完了条件: 権利・AI表示の要否を確認済み
- 引き継ぎ: 20動画編集へ

### 18 図解作成
- 目的: 比較表や手順を図にする
- 入力: 台本、検証表
- 手順: 図案 → 数値は検証済みのみ
- 出力: 図解画像
- 完了条件: 数値が検証表と一致
- 引き継ぎ: 20動画編集へ

## フェーズ5 編集(19〜22)

### 19 字幕作成
- 目的: 読みやすい字幕を作る
- 入力: 台本
- 手順: 分割 → タイミング付け
- 出力: 字幕ファイル
- 完了条件: 誤字なし、台本と一致
- 引き継ぎ: 20動画編集へ

### 20 動画編集
- 目的: リール動画を組み立てる
- 入力: 台本、素材、字幕、図解
- 手順: 構成通りに編集 → 縦型・尺を確認
- 出力: 動画ファイル
- 完了条件: 構成表と一致
- 引き継ぎ: 21音声調整へ

### 21 音声調整
- 目的: 音量・音質・BGMを整える
- 入力: 動画、音源
- 手順: ナレーションとBGMのバランス調整。BGMは商用利用可能なもののみ
- 出力: 音声調整済み動画
- 完了条件: 音源の権利記録あり
- 引き継ぎ: 22品質確認へ

### 22 品質確認
- 目的: 公開前の最終点検
- 入力: 動画、台本、検証表
- 手順: 台本一致、誤字、PR表記、権利、AIラベルを確認
- 出力: 品質チェック表
- 完了条件: 全項目合格。**公開承認は本人**
- 引き継ぎ: 23投稿管理へ

## フェーズ6 投稿・分析(23〜28)

### 23 投稿管理
- 目的: 投稿スケジュールと記録を管理する
- 入力: 承認済み動画、キャプション
- 手順: 投稿案を作成 → 本人が投稿(または承認のうえ実行)
- 出力: 投稿台帳
- 完了条件: 投稿日時とURLを記録
- 引き継ぎ: 25コメント分析、26数値分析へ

### 24 キャプション作成
- 目的: キャプションとハッシュタグを作る
- 入力: 台本、CTA
- 手順: 本文 → PR表記 → ハッシュタグ(根拠のある数)
- 出力: キャプション案
- 完了条件: PR表記あり、NG表現なし
- 引き継ぎ: 23投稿管理へ(22品質確認と並行)

### 25 コメント分析
- 目的: 反応と要望を抽出する
- 入力: コメント
- 手順: 分類 → 質問・不満を抽出。返信は案のみ
- 出力: コメント分析メモ
- 完了条件: 要望が分類済み
- 引き継ぎ: 27改善提案へ

### 26 数値分析
- 目的: 指標を集計して把握する
- 入力: インサイト、ASP管理画面の数値
- 手順: brand.yamlのmetricsを集計。サンプルが少ない場合は結論を出さない
- 出力: 数値レポート
- 完了条件: 数値の取得元が明記されている
- 引き継ぎ: 27改善提案へ

### 27 改善提案
- 目的: 次の施策を提案する
- 入力: 数値レポート、コメント分析
- 手順: 仮説 → 施策 → 検証方法
- 出力: 改善提案書(rules更新案を含む)
- 完了条件: 根拠データが示されている。ルール更新は本人の承認後に反映
- 引き継ぎ: 28進行管理へ。次回の06企画立案

### 28 進行管理
- 目的: 全体の進行と承認待ちを管理する
- 入力: 全担当の出力
- 手順: 依頼の受付 → 不足情報の質問 → 各担当へ引き継ぎ → 進捗と承認待ちの一覧化
- 出力: 進行表
- 完了条件: 承認待ちが一覧化されている
- 引き継ぎ: 全担当

## 責任範囲の整理(重複しやすい箇所)
| 重複 | 整理 |
|---|---|
| 13台本レビュー / 14事実確認 / 15表現チェック | 13=構成・分かりやすさ、14=事実の真偽、15=法令・NG表現。1つの観点は1担当のみ |
| 11タイトル / 12CTA / 24キャプション | 11=動画内、12=行動設計、24=投稿文 |
| 17画像生成 / 18図解作成 | 17=写真風・イラスト、18=数値や手順を含む図 |
| 22品質確認 / 15表現チェック | 15=台本の文言、22=完成動画の最終点検 |
| 26数値分析 / 27改善提案 | 26=事実の集計のみ、27=解釈と提案 |
| 01市場調査 / 04トレンド調査 | 01=構造的な需要、04=短期の話題・季節 |
